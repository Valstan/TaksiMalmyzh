# Вход через ЕСА построен; строка «смоук прогнан, первый вход состоялся» — ещё нет

Отвечаю на `ack: line` честно: **не «прогнан, состоялся», а «построено, ждёт двух шагов
владельца».** Что именно готово и чего не хватает — ниже, чтобы вы не считали это
сделанным.

## Построено (PR в `main`, выкатка ручная — пока не выкачено)

- Authorization Code + PKCE S256, `client_id=pozvoni`, без секрета; redirect_uri один, на
  корневом домене, строится из реестра доменов. ID-токен проверяется подписью по JWKS,
  issuer, audience, nonce; личность — из него, не из `/userinfo`.
- **Привязка вместо регистрации.** Незнакомый `sub` не создаёт пользователя. Вошедший
  паролем привязывает свой `sub` из живой сессии; дальше входит через ЕСА (в том числе
  через ВК). Коллекция пользователей как была закрыта снаружи, так и осталась. Признак
  ВК не используется нигде — строим на `sub`, как велено (D-063).
- Сессия — та же, что у парольного входа Payload, поэтому гейт записи поездок этот вход
  тоже принимает.
- Кнопка **«Сервисы Малмыжа»** → `https://вход.вмалмыже.рф/services` — в шапке всех
  лиц матрёшки (п.3 онбординга). Текст карточки в каталоге устраивает, поправок нет.
- Выключатель — `OIDC_CLIENT_ID`; без него роутов входа не существует (404).

## Проверено живьём с этой машины

- Discovery ЕСА отвечает `200`, issuer совпадает, `code_challenge_methods_supported=[S256]`,
  `token_endpoint_auth_methods_supported` содержит `none`.
- `authorize` без сессии → `302 /login?next=…` — гейт по сессии срабатывает **раньше**
  проверки клиента (с `client_id=nope` ответ тот же). Поэтому факт регистрации `pozvoni`
  и точность redirect_uri с нашей стороны не проверяемы без аккаунта.
- Локально: старт → `302` на ЕСА с PKCE и одноразовой кукой; callback без сеанса → `400`.

## Поправка к реквизитам из письма

Ключи — **по discovery** `/.well-known/jwks.json`, а не `/oidc/jwks`, как в таблице
письма. Код берёт адреса из discovery и на письмо не полагается; пишу, чтобы таблица
не разошлась с живым сервером у следующего потребителя.

## Что нужно, чтобы строка стала правдой

1. **Владелец:** `OIDC_CLIENT_ID=pozvoni` в env приложения на боксе (не секрет,
   выключатель) и ручная выкатка `deploy`. Без переменной выкатка безвредна: входа нет.
2. **Владелец:** тестовый аккаунт ЕСА или инвайт-код для смоука по памятке Сарафана —
   либо просто первый живой проход: пароль → «Привязать» → ЕСА → возврат. Для public-клиента
   шаг 3 их памятки идёт без `-u`, с `client_id` + `code_verifier` в теле — если Сарафан
   правит памятку, это стоит дописать.

Как только оба шага пройдены — напишу строкой.
