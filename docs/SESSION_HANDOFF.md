## Матрёшка доменов — что построено 2026-08-30

Одно приложение показывает разные лица по заголовку `Host`; ни редиректов, ни разных сборок.

- **Реестр** — `lib/sites.ts`: хост в punycode + кириллическая форма + уровень
  (`service` / `category` / `business`) + категории справочника + флаг `live`. Инварианты
  проверяются **на импорте модуля**: `new URL()` обязан превратить кириллицу в тот же
  punycode, иначе сборка падает. Без этого опечатка ломалась бы тихо — хост никогда не
  совпал бы, и домен молча показывал бы корень.
- **Флаг `live`** — домен может быть заведён в коде и не существовать в DNS. Пока `false`,
  скоуп работает, но абсолютных ссылок на домен никто не строит; ссылка «весь ПОЗВОНИ»
  ведёт на `/nomera?scope=all` в текущем домене. Код уедет в прод заранее и **включится
  сам** в день заведения домена — без второй выкатки.
- **Скоуп**: `такси.` показывает только такси (главная начинается с номеров, карта ниже),
  `услуги.` — мастеров + бригады + доставку, `магазины.` — магазины, корень — всё.
- **Крошки** «ПОЗВОНИ › ТАКСИ МАЛМЫЖ» — иначе поддомен выглядит отдельным сайтом.
- **nginx** — одна секция на все домены (`server_name` списком), `--domain` в
  `bootstrap-box.sh` принимает несколько через пробел. Добавить домен = перезапустить
  скрипт с полным списком.
- **Смоук** принимает несколько публичных адресов (`DEPLOY_SMOKE_URL` через пробел).
  Заодно починена ложная зелень: `ssl_verify_result` равен 0 и без TLS, то есть
  `http://`-адрес отчитывался бы «сертификат валиден».

Проверено локально подменой `Host` на четырёх доменах: скоуп, крошки, `?scope=all`,
абсолютные ссылки при `live: true`, canonical, заголовки вкладки.

**`такси.вмалмыже.рф` не удалять и не редиректить** — решение владельца: домен, который
однажды работал, известен людям, по нему приходят и через год.

## Как это устроено (для следующей сессии)

- **Стек**: Next 16 + React 19 + TS; Payload 3.88 + PostgreSQL (`@payloadcms/db-postgres`).
  Коллекции: `users` (вход логином, без почты), `entries` (справочник). Конфиг —
  `payload.config.ts`, миграции — `migrations/`, применяются **на старте прода** через
  `prodMigrations` (на боксе нет CLI — G20).
- **Гейт публикации** — в access-правиле `entries`: анониму отдаётся только
  `status=published`, по всем каналам; страницы ходят с `overrideAccess: false`.
- **Сид** (`payload.config.ts onInit`): на пустой базе — супер-админ и черновики из
  `seed/directory-draft.ts` (8 номеров, у каждого источник; два подозрения отмечены).
- **Предложения посетителей**: `/api/suggest` — honeypot, общий потолок частоты (не
  по-IP — IP не собираем), статус жёстко `draft`.
- **Выкатка**: workflow `deploy` (ручной) — сборка в CI, пакет ≈ 43 МиБ, доставка, симлинк,
  рестарт, смоук на боксе. Локальная проверка релиза: `npm run build && npm run package`,
  запустить `release/server.js` с env из `.env.local`.
- **Локальная БД**: `npm run db:setup` (идемпотентно). Прод-БД на боксе заведена, секреты в
  `shared/.env` вне репозитория.
- **Локальная проверка доменов**: `http://такси.localhost:3000` — браузер сам резолвит
  `*.localhost`, hosts-файл править не нужно.

## Уроки сессий (кратко; разборы — в письмах to-brain)

- `ProtectHome=true` при приложении в `/home` = `200/CHDIR` и цикл рестартов; выглядит как
  проблема прав. `MemoryMax` на общем боксе — обязанность перед соседями (у нас 640M).
- Домен на этом хостинге резолвится в адрес прокси, не бокса — проверять надо ответ по
  адресу, а не запись в DNS (потерял час).
- Публичный смоук с раннера GitHub невозможен (не достучался до РФ-хоста) — проверять с
  бокса.
- Стиль `@protomaps/basemaps` по умолчанию тянет шрифты с чужого хоста; «self-hosted»
  библиотека ≠ self-hosted трафик, ловит только сетевой замер страницы.
- D-046 нарушал (heredoc в командах) — каждый раз переделывал файлом; правило работает.
- **Проверка, которая не может провалиться, хуже отсутствующей**: `ssl_verify_result`
  возвращает 0 и там, где TLS не было, — проверка сертификата выдавала разрешение, которого
  не проверяла.
- **Тихая поломка в реестре доменов дороже громкой**: неверный punycode не совпадёт ни с
  чем и молча покажет корень вместо нужного лица. Поэтому инвариант проверяется на импорте
  модуля, а не глазами при ревью.
