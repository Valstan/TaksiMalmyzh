## Как это устроено (для следующей сессии)

- **Стек**: Next 16 + React 19 + TS; Payload 3.88 + PostgreSQL (`@payloadcms/db-postgres`).
  Коллекции: `users` (вход логином, без почты), `entries` (справочник). Конфиг —
  `payload.config.ts`, миграции — `migrations/`, применяются **на старте прода** через
  `prodMigrations` (на боксе нет CLI — G20).
- **Гейт публикации** — в access-правиле `entries`: анониму отдаётся только
  `status=published`, по всем каналам; страница ходит с `overrideAccess: false`.
- **Сид** (`payload.config.ts onInit`): на пустой базе — супер-админ `admin`/`admin` и
  черновики из `seed/directory-draft.ts` (8 номеров, у каждого источник; два подозрения
  отмечены в самих записях).
- **Предложения посетителей**: `/api/suggest` — honeypot, общий потолок частоты (не
  по-IP — IP не собираем), статус жёстко `draft`.
- **Выкатка**: workflow `deploy` (ручной) — сборка в CI (env-заглушки для payload.config),
  пакет ≈ 43 МиБ, доставка, симлинк, рестарт, смоук на боксе (страница, поиск, Range карты,
  `/nomera`, публичный URL с сертификатом). Локальная проверка релиза: собрать
  `npm run build && npm run package`, запустить `release/server.js` с env из `.env.local`.
- **Локальная БД**: `npm run db:setup` (идемпотентно). Прод-БД `taksi_prod` на боксе
  заведена, секреты в `shared/.env` вне репозитория.

## Что ждёт владельца (по убыванию срочности)

1. **Сменить пароль супер-админа** — `/admin`, вход `admin`/`admin`, страница аккаунта →
   Change Password (и логин там же). До смены вход защищён только незнанием пароля, а
   репозиторий публичный. Сид одноразовый (только пустая таблица), но тянуть не стоит.
2. **Проверить 8 номеров** в админке звонком и перевести верные в «Опубликован». Подозрения
   отмечены: общий номер у «Ветра» и «Круиза»; межгородние записи — агрегаторы.
3. Письменное принятие риска этапа A (M0.A §8.0) — к спринту 3.
