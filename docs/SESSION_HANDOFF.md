## Матрёшка доменов — что построено 2026-08-30

Одно приложение показывает разные лица по заголовку `Host`; ни редиректов, ни разных сборок.

- **Реестр** — `lib/sites.ts`: хост в punycode + кириллическая форма + уровень
  (`service` / `category` / `business`) + категории справочника + флаг `live`. Инварианты
  проверяются **на импорте модуля**: `new URL()` обязан превратить кириллицу в тот же
  punycode, иначе сборка падает. Без этого опечатка ломалась бы тихо — хост никогда не
  совпал бы, и домен молча показывал бы корень.
- **Флаг `live`** — домен может быть заведён в коде и не существовать в DNS. Пока `false`,
  скоуп работает, но абсолютных ссылок на домен никто не строит; ссылка «весь ПОЗВОНИ»
  ведёт на `/nomera?scope=all` в текущем домене. Скоуп нового домена включается сам, как
  только домен доедет до DNS и `server_name` — код уже в проде. А `live: true` — правка
  `lib/sites.ts`: отдельный PR и своя выкатка (так и было с `позвони.`: PR #31, выкатка
  2026-08-30).
- **Скоуп**: `такси.` показывает только такси (главная начинается с номеров, карта ниже),
  `услуги.` — мастеров + бригады + доставку, `магазины.` — магазины, корень — всё.
- **Крошки** «ПОЗВОНИ › ТАКСИ МАЛМЫЖ» — иначе поддомен выглядит отдельным сайтом.
- **nginx** — одна секция на все домены (`server_name` списком), `--domain` в
  `bootstrap-box.sh` принимает несколько через пробел. Добавить домен = перезапустить
  скрипт с полным списком.
- **Смоук** принимает несколько публичных адресов (`DEPLOY_SMOKE_URL` через пробел).
  Заодно починена ложная зелень: `ssl_verify_result` равен 0 и без TLS, то есть
  `http://`-адрес отчитывался бы «сертификат валиден».

Проверено локально подменой `Host` на четырёх доменах: скоуп, крошки, `?scope=all`,
абсолютные ссылки при `live: true`, canonical, заголовки вкладки.

**`такси.вмалмыже.рф` не удалять и не редиректить** — решение владельца: домен, который
однажды работал, известен людям, по нему приходят и через год.

## Как это устроено (для следующей сессии)

- **Стек**: Next 16 + React 19 + TS; Payload 3.88 + PostgreSQL (`@payloadcms/db-postgres`).
  Коллекции Payload две: `users` (вход логином, без почты; с 2026-09-02 — роль
  `superadmin`/`user`, имя из ЕСА и `oidcSub`) и `entries` (справочник). Рядом три схемы
  **вне** Payload, каждая со своим DDL: `track` (`lib/track-ddl.ts`), `crowd`
  (`lib/crowd-ddl.ts`), `market` (`lib/market-ddl.ts`) — они намеренно лежат отдельно от
  `public`, чтобы интроспекция Payload их не касалась. Конфиг —
  `payload.config.ts`, миграции — `migrations/`, применяются **на старте прода** через
  `prodMigrations` (на боксе нет CLI — G20).
- **Гейт публикации** — в access-правиле `entries`: анониму отдаётся только
  `status=published`, по всем каналам; страницы ходят с `overrideAccess: false`.
- **Сид** (`payload.config.ts onInit`): на пустой базе — супер-админ и черновики из
  `seed/directory-draft.ts` (8 номеров, у каждого источник; два подозрения отмечены).
- **Предложения посетителей**: `/api/suggest` — honeypot, общий потолок частоты (не
  по-IP — IP не собираем), статус жёстко `draft`.
- **Выкатка**: workflow `deploy` (ручной) — сборка в CI, пакет ≈ 69 МиБ (замер прогона
  выкатки 2026-09-02), доставка, симлинк, рестарт, смоук на боксе. Локальная проверка
  релиза: `npm run build && npm run package`, запустить `release/server.js` с env из
  `.env.local`.
- **Локальная БД**: `npm run db:setup` (идемпотентно). Прод-БД на боксе заведена, секреты в
  `shared/.env` вне репозитория.
- **Локальная проверка доменов**: `http://такси.localhost:3000` — браузер сам резолвит
  `*.localhost`, hosts-файл править не нужно.

## Карта на проде: один настоящий баг и один призрак

**Итог: карта работает на обоих доменах.** Проверено в браузере с активной вкладкой.

### Настоящий баг (починен, PR #32)

nginx отдаёт `/map/` напрямую, минуя Next, а в стоковом `mime.types` нет `.mjs` — воркер
MapLibre уезжал браузеру как `application/octet-stream`, и модульный скрипт с не-JS типом
браузер исполнять отказывается. Карта у пользователей действительно не работала.

Локально баг невидим по построению: в разработке тот же файл отдаёт Next, который тип
знает. **Тот же файл, отданный другим сервером, — другой файл.**

Вторая половина той же правки — про кэш: `/map/` отдаётся с `immutable` на год, то есть
с обещанием, что по адресу навсегда те же байты **и заголовки**. Обещание было нарушено,
и сломанный тип залипал у посетителей на год; правка на сервере таких посетителей не
догоняет. Поэтому воркер переехал в каталог с версией MapLibre в пути — адрес меняется
вместе с файлом. Заодно закрылся латентный баг: апгрейд `maplibre-gl` менял содержимое
воркера, не меняя адреса.

### Призрак: два часа отладки серого прямоугольника, которого не было

После починки MIME карта в моих проверках оставалась серой, и я записал это как открытый
баг. Баг был в измерении.

**`requestAnimationFrame` не срабатывает в скрытой вкладке, а MapLibre именно на нём
откладывает загрузку стиля** (`Style.loadJSON` → `browser.frameAsync`). Во вкладке, которую
никто не показывает, карта навсегда остаётся в состоянии «канвас есть, стиль не начат»:
ни одного запроса спрайтов, тайлов и глифов, ни одного события, ни одной ошибки в консоли.
Ровно та картина, которую я принимал за поломку.

Диагноз занял два часа, потому что сигнатура «зелено всё, кроме результата» уводит в
инфраструктуру. Было исключено измерением: MIME, кэш браузера, порча байтов nginx
(SHA-256 совпал), nginx как таковой (временно убирал `location /map/`), прокси хостера
(заголовки идентичны), артефакт CI против локальной сборки (**все чанки побайтово равны**),
https против http (туннель к прод-приложению напрямую), панель браузера против настоящего
Chrome, загрузка машины. Развязка пришла из одной строки диагностики в коде: `getStyle()`
вернул пусто, а журнал событий карты оказался пуст целиком — значит стиль не начинался, а
не падал.

**Правило на будущее:** всё, что рисуется через canvas/анимацию — карта, графики,
анимации, — **нельзя проверять скриншотом скрытой вкладки**. Вкладку надо вывести на
передний план, а до того единственная надёжная проверка — не картинка, а состояние:
`document.visibilityState`, список сетевых запросов, события объекта. Скриншот скрытой
вкладки отвечает на вопрос «что нарисовано», а не «что работает», и эти ответы расходятся.

## Запись поездок ВКЛЮЧЕНА на проде (2026-08-30)

Гейт этапа A открыт: `TRACK_RECORDING=on` в окружении службы. Эндпоинт отвечает 401 без
входа — то есть работает и закрыт. Проверено на проде: без сессии 401, после входа старт
проходит, точка принимается и шифруется, завершение сохраняет причину; тестовые поездки
удалены.

Общего токена, который был здесь в первой редакции, больше нет — ни в коде, ни на боксе:
файл затёрт и удалён, credential отключён. Неиспользуемый секрет опаснее используемого —
про него забывают и не ротируют.

### Токена нет вовсе — право записи даёт роль супер-админа

Сначала был общий токен: он генерировался на сервере, и владельцу предлагалось его
**прочитать**, чтобы ввести на телефоне. 2026-08-30 это ровно так и провалилось —
прочитанный секрет уехал в переписку, и его пришлось менять.

Вывод шире одного токена: **процедура, в которой есть шаг «прочитай секрет глазами», рано
или поздно этот секрет разгласит.** Дело не в аккуратности человека — прочитанное
показывают, копируют и вставляют, потому что иначе им нельзя воспользоваться.

Поэтому токена больше нет. Запись разрешена тому, кто **вошёл** в приложение обычной
сессией — той же, что и в админке. Но с 2026-09-02 «вошёл» больше не значит «владелец»:
единый вход экосистемы заводит посетителю аккаунт сам при первом входе, поэтому гейт
проверяет роль и пускает к записи только `superadmin` (PR #49, `lib/track-gate.ts`).
Ввести на телефоне нужно ноль символов.

Как поехать: открыть `позвони.вмалмыже.рф/admin`, войти, перейти на `/zapis`, нажать
«Начать поездку». Если не вошёл, страница честно скажет об этом и даст ссылку на вход.

Сессия нужна только на **старте**: дальше поездка живёт своим токеном записи, потому что
поездка длится часами и сессия может истечь по дороге. Поездка при этом **не связывается с
аккаунтом** — в её строке псевдоним установки, а не пользователь: забор M0.A §10 про то, что
записи Фазы 1 не соединяются с аккаунтами Фазы 2, открывать ради удобства нельзя.

### Запись не висит вечно: лестница напоминаний и автозавершение

Если ничего не движется **10 минут**, приложение спрашивает «вы ещё записываете?» — вибрацией
и звуком, крупным блоком с одной кнопкой, а не диалогом браузера. Дальше ещё два напоминания
с паузой в **5 минут**. Если не ответили ни на одно — запись завершается сама и помечается
причиной `idle`.

Числа взяты из мировой практики трекеров (автопауза через минуты, напоминание через десяток
минут, автозавершение через полчаса) и намеренно ближе к её нижней границе: у продукта
безопасности висящая «активная поездка», про которую все забыли, обесценивает саму идею.

⚠️ **Тот же механизм — половина «мёртвой руки» (M0.A §5.3).** Неподвижность и молчание
означают ЛИБО «забыл выключить», ЛИБО «что-то случилось», и различить их нельзя ничем, кроме
вопроса самому человеку. Поэтому напоминания — не удобство, а дискриминатор, а
`finish_reason` — вход для лестницы эскалации спринта 4. Постфактум эти два случая не
отличить: трасса у обоих одинаковая, стоит на месте.

⚠️ Числа подлежат настройке на реальных поездках: §5.3 называет порог «норма или тревога»
центральной нерешённой задачей, а §8.6 оставляет бюджет ложных срабатываний за владельцем.
Собраны в одном месте — константа `IDLE` в `components/TripRecorder.tsx`.

⚠️ **Границы этапа A не отменены принятием риска.** Записывать только там, где нет наёмного
водителя: за рулём своей машины, на велосипеде, пешком. Первая поездка с наёмным водителем —
такая же граница A→B, как и первый посторонний пассажир (M0.A §8.0).

Когда замеры закончатся, запись стоит выключить: одна строка `TRACK_RECORDING=off` в
`shared/.env` и рестарт службы. Пока она включена, посторонних от этапа B отделяет не сам
вход в приложение (аккаунт через ЕСА теперь заводит себе любой), а роль `superadmin` —
учётка персонала: пароль супер-админа либо привязанный к ней единый вход. Она же и ключ

## Чем обосновано устройство схемы

Полный разбор — [`TRIP_SCHEMA.md`](TRIP_SCHEMA.md); здесь то, что стоит помнить, не открывая
его.

Решено (моё инженерное решение, не владельца): построчный AEAD ChaCha20-Poly1305 со
**случайным хранимым** nonce, конвертная схема ключей, `pt bytea(47)`, открытыми остаются
только `day`, `trip_id`, `seq`. **126,9 Б/точку** против 94,0 у потокового шифра. Потоковый
отвергнут потому, что весь Малмыж укладывается в 0,03° по оси: старшие биты координат
постоянны для города, и противник с правом записи смещает координату не зная ключа.

Четыре поправки к M0.A, найденные замером: надбавка AEAD **+33, а не +28** Б/точку; развилка
шифрования **трёхточечная (0/+16/+33)**, а не двухточечная; **ширина `trip_id` — рычаг
крупнее всего спора о шифровании** (`bigint` +16 Б, `uuid` +26 Б), и в M0.A его нет;
утверждение §4.2 «строки поездок на порядки меньше» **неверно** (20,6 против 27,2 МиБ).

Проверено руками, не по памяти: `ON CONFLICT (trip_id, seq)` на партиционированной таблице
не компилируется (M0.A прав); идемпотентная досылка через границу партиций работает; вставка
в день без партиции падает жёстко; `DETACH … CONCURRENTLY` запрещён внутри транзакции **и при
живой `DEFAULT`-партиции** — поэтому `DEFAULT`-партиции не будет: она лишает ретеншн
единственного способа не блокировать приём. В Node этого проекта есть `chacha20-poly1305`,
но **нет** `aes-256-gcm-siv` и `xchacha20-poly1305`.

## Уроки сессий (кратко; разборы — в письмах to-brain)

- `ProtectHome=true` при приложении в каталоге, который эта опция скрывает, = `200/CHDIR`
  и цикл рестартов; выглядит как проблема прав. `MemoryMax` на общем боксе — обязанность
  перед соседями (у нас 640M).
- Домен на этом хостинге резолвится в адрес прокси, не бокса — проверять надо ответ по
  адресу, а не запись в DNS (потерял час).
- Публичный смоук с раннера GitHub невозможен (не достучался до РФ-хоста) — проверять с
  бокса. С рабочей машины канал к РФ-хостам тоже пропадает целиком (04.09: ни прод, ни
  бокс, ни ЕСА, при живом GitHub) — тогда всё, что требует прода, идёт через Actions.
- **CSP `form-action` проверяет и адрес редиректа после отправки формы, а не только адрес
  самой формы.** Выход, сделанный формой, с редиректом на чужой хост браузер обрывает
  молча: ошибка только в консоли, а симптом неотличим от «редирект не поставили» (04.09,
  выход из ЕСА).
- Стиль `@protomaps/basemaps` по умолчанию тянет шрифты с чужого хоста; «self-hosted»
  библиотека ≠ self-hosted трафик, ловит только сетевой замер страницы.
- D-046 нарушал (heredoc в командах) — каждый раз переделывал файлом; правило работает.
- **Проверка, которая не может провалиться, хуже отсутствующей**: `ssl_verify_result`
  возвращает 0 и там, где TLS не было, — проверка сертификата выдавала разрешение, которого
  не проверяла.
- **Тихая поломка в реестре доменов дороже громкой**: неверный punycode не совпадёт ни с
  чем и молча покажет корень вместо нужного лица. Поэтому инвариант проверяется на импорте
  модуля, а не глазами при ревью.
- **Зелёный код ответа ничего не говорит о том, чей сайт отвечает.** Новый домен отдавал
  `200` с валидным сертификатом — и сайт соседа. Проверка домена — это проверка содержимого.
- **`immutable` — обещание, а не оптимизация.** nginx отдавал `/map/` с `max-age=1 год,
  immutable`, а в его `mime.types` не было `.mjs`: воркер MapLibre уехал посетителям как
  `application/octet-stream` и **закэшировался таким на год**. Правка на сервере таких
  посетителей уже не догоняет — лечит только новый адрес. Поэтому воркер теперь лежит в
  каталоге, названном версией MapLibre: адрес меняется вместе с файлом. Версия в пути, а
  не в `?v=` — воркер импортирует соседний `shared.mjs` относительным путём, и query до
  него не доезжает.
- **Тот же файл, отданный другим сервером, — другой файл.** Локально `/map/` отдаёт Next
  (тип знает), на проде — nginx в обход Next (тип берёт из своей таблицы). Баг был
  невидим в разработке по построению. Прод-сборка, поднятая локально, отделила сборку от
  сервера за пять минут и стоит того, чтобы делать это раньше догадок.
- **Серый прямоугольник вместо карты — это не одна поломка, а класс.** Воркер умирает
  внутри себя, главный поток об этом не узнаёт, `map.on("error")` молчит, консоль чиста.
  Поэтому `check-assets.mjs` теперь проверяет оба файла воркера: тихую поломку ловят
  проверкой наличия, а не наблюдением.
- 🔻 **Процедура со словами «прочитай секрет» разгласит этот секрет.** Токен этапа A
  генерировался на сервере и предлагался к прочтению — и в тот же день уехал в переписку.
  Дело не в аккуратности человека: прочитанное показывают, копируют и вставляют, потому что
  иначе им нельзя воспользоваться. Первое лечение было половинчатым — «пусть владелец сам
  придумает токен»: шаг чтения исчез, но сущность осталась. Настоящее лечение — заметить,
  что **секрет вообще не нужен**: вошедший в приложение уже доказал право, и токен был
  лишней сущностью, которую надо порождать, хранить, доставлять и ротировать. Секрета,
  которого нет, не утекает.
- 🔻 **Главный урок дня: скриншот скрытой вкладки — не проверка.** В скрытой вкладке не
  срабатывает `requestAnimationFrame`, а MapLibre на нём откладывает загрузку стиля. Карта
  навсегда остаётся серой, событий ноль, ошибок ноль — и это неотличимо от настоящей
  поломки. Два часа отладки ушло на призрак. Всё, что рисуется через canvas или анимацию,
  проверяется на **выведенной вперёд** вкладке; до того верить можно только состоянию
  (`document.visibilityState`, сеть, события), а не картинке.
- **Симптом «зелено всё, кроме результата» уводит в инфраструктуру.** За два часа было
  исключено измерением девять гипотез — от MIME до побайтового сравнения чанков CI и
  локальной сборки, — и ни одна не была причиной. Развязку дала одна строка диагностики
  внутри кода: пустой `getStyle()` и пустой журнал событий карты сразу показали, что стиль
  не падает, а **не начинается**. Заглядывать внутрь объекта надо было на полчаса раньше,
  чем перебирать слои снаружи.
- 🔻 **Предупреждение в комментарии не защищает код под ним.** Миграция с `ADD VALUE`
  несла комментарий «новое значение в той же транзакции использовать нельзя» — и следующей
  строкой использовала его. Комментарий читал ревьюер, а не PostgreSQL. Защищает только
  прогон против базы, где enum уже есть; CI на пустой базе такое не ловит.
- **G30 ловит и того, кто про него написал.** В комментарии к смоуку в `deploy.yml` слой
  «ssh склеивает, удалённый шелл разбирает» описан моей же рукой — и через час список
  доменов, переданный одной строкой в кавычках, развалился ровно на нём. Знание слоя не
  заменяет привычку передавать список отдельными аргументами.
- 🔻 **Правило доступа, написанное для одного класса пользователей, становится дырой, когда
  появляется второй.** В `entries` стояло `update: Boolean(req.user)` — верно, пока
  «вошедший» = владелец. С автосозданием посетителей через ЕСА любой, кто вошёл через ВК,
  правил бы номера через REST. Найдено при постройке спринта 8, закрыто ролью
  (`collections/Entries.ts`). Каждое правило «для вошедшего» пересматривается в тот день,
  когда в системе появляется новый класс входящих, — само оно не портится, портится мир
  вокруг него.
- **За nginx `request.url` в Next — адрес самой службы, а не публичный домен.** Редирект
  после первого живого входа через ЕСА увёл владельца на адрес процесса. Лечится origin из
  реестра доменов (`publicOrigin()`), а не из запроса; от того же origin зависит флаг
  `Secure` у кук — локально его нет, в проде обязан быть.

## Правило продолжения

Любая модель начинает с `AGENTS.md`, затем входящие brain (двухканально, чужие репо только
чтение) и этот handoff. Предыдущий чат не нужен для восстановления контекста.

Handoff пишется **по шагам нитки**, а не только при закрытии сессии: смержил PR — обновил
«где мы» и «что дальше» (рекомендация brain 2026-09-02). Тогда обрыв и сжатие контекста
ничего не теряют, а `close_session` — страховка, а не единственная точка записи. Правка
handoff едет **в том же PR, что и работа**, которую она описывает (письмо brain
2026-09-02): отдельный PR на документ разъезжается с кодом ровно на то время, пока висит.
