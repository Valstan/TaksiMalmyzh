## 1. Фазовое видение

Двусторонний маркетплейс через одностороннюю пользу: сперва решаем безопасность пассажира и набираем спрос → потом онбордим предложение (таксопарки) → монетизируем конкуренцию за видимость.

| Фаза | Что | Роль |
|---|---|---|
| **Ф1 — безопасность пассажира** | Пассажир включает поездку, приложение трекает маршрут как подстраховку («найти пропавшего»). Анонимно, без слежки. | MVP, ядро роста |
| **Ф2 — таксопарки** | Таксопарки регистрируются, предлагают услуги; пользователи делают заказы в приложении. | Онбординг предложения |
| **Ф3 — монетизация** | Фирмы конкурируют за показы (аукцион / featured-листинги). | Маркетплейс |

Ставка: односторонняя польза (безопасность) должна быть достаточно ценной **сама по себе**, чтобы набрать аудиторию до появления таксопарков.

## 2. MVP Фазы 1 (строим первым)

1. **Запись поездки:** старт/стоп, гео-трасса (точки + таймстемпы), точки выезда/прибытия, дата/время.
2. **Хранение трассы, переживающее потерю телефона** — иначе цель «найти пропавшего» не достигается (см. §4).
3. **Шаринг поездки с доверенным контактом** (live во время поездки и/или итог) — главный механизм «найти/подстраховать».
4. **История поездок** пользователя.
5. **Анонимность by-design** — без рекламной личности, без скрытой слежки; видимый foreground-индикатор «идёт запись поездки».

## 3. Предложенный стек (🔶 PROPOSED — НЕ решён окончательно)

Ниже — **предложение Мозга, а не финальное решение.** Утверждается на стадии разработки после probe (§5).

| Слой | Предложение | Почему |
|---|---|---|
| **Бэкенд + админка** | Payload CMS + Next.js + PostgreSQL (= стек GONBA/Sabantuy экосистемы) | роли/auth, админка для таксопарков (Ф2), schema-as-код, REST/GraphQL клиенту, переиспользование компетенции |
| **Клиент** | **React, обёрнутый Capacitor** (фоновый GPS), Android APK без стора | чистый PWA фоновую геолокацию надёжно не тянет (§4); общий код с проектом trener |
| **Гео-трекинг** | device GPS + Capacitor background-geolocation (Android foreground-service) | надёжный фон — только через нативную обёртку |
| **Карты** | РФ-провайдер: Яндекс.Карты / 2ГИС / OSM (не Google) | geo-block/платность Google; tech-radar `assess` |
| **Хостинг/секреты** | Ubuntu + РФ-VPS; `/etc/<app>/.env`; CI standalone | 152-ФЗ — хранение геоданных в РФ |

**Открытый вопрос платформы:** iPhone + фоновый GPS + «без стора» ≈ недостижимо. Варианты (решение владельца при go):
- Android APK без стора с фоновым сервисом (iPhone позже / foreground-only) — **дешевле, но iPhone-фон в MVP хромает**;
- Capacitor + App Store для iOS-фона — **требует Mac + Apple Developer $99/год + модерация**;
- сверх-простой старт: PWA foreground-only — **фон не работает, «убрал телефон» теряет трек**.

## 4. Ключевые риски

- **Фоновый GPS ломает чистый PWA.** Браузеры приостанавливают фоновый JS; на iOS фоновой web-геолокации практически нет. Надёжный трекинг «телефон в кармане» требует нативной обёртки (Capacitor). На iPhone фон почти наверняка упрётся в App Store. → это же определяет выбор платформы и стека клиента.
- **Приватность геоданных + 152-ФЗ.** Геолокация — чувствительные перс. данные; даже «анонимный» трек может реидентифицировать. Требуется явное согласие, минимизация, хранение в РФ, прозрачность. **Внутреннее противоречие:** «анонимно/без слежки» ↔ «трасса извлекаема, чтобы найти пропавшего» — это решается **дизайном** (псевдонимность, шифрование/шаринг по ключу, не строить рекламный профиль на гео), а не откладывается. Анти-цель: приложение не должно стать инструментом скрытой слежки.
- **Two-sided cold-start.** Вся ставка — «сперва популярность у пассажиров, потом подтянутся таксопарки». Если безопасность не наберёт аудиторию сама по себе — предложение не придёт.
- *(смежные)* Батарея от непрерывного GPS (риск, что удалят/выключат); ответственность позиционирования «найти пропавшего» — формулировать как «подстраховка/лог», не гарантия спасения; лимиты/стоимость карт-провайдера в РФ.

## 5. Следующие шаги

1. **Probe-before-build фоновой геолокации** — живой capability-probe на реальных Android/iOS: что ОС реально отдаёт в фоне / Doze; плюс probe API карт-провайдера (лимиты, geo-block). Не верить докам.
2. **Решить платформу** (§3): Capacitor + APK vs App Store для iOS-фона vs PWA foreground-only. Это и продуктовое, и бюджетное решение владельца.
3. **Дизайн приватности** (§4) — центральный вопрос: как трасса переживает потерю телефона, оставаясь псевдонимной и не-слежечной (шифрование, шаринг по ключу, ретеншн/прореживание точек). Продуктовое + юридическое (152-ФЗ) решение.
4. После probe + решений: финализировать стек, tech-radar (`assess`), scaffold Payload+Next+Capacitor, затем Ф1.
