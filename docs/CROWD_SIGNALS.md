# Краудсигналы по номерам — спринт 5

Построено 2026-09-03. Первый пользовательский ввод в продукте — о **бизнесах**, не о людях.

## Что видит посетитель

- Нажал номер → ушёл в звонилку → вернулся: под номером вопрос **«Дозвонились?»** с кнопками
  «Да» / «Не ответили», флажок «цена не совпала с указанной», «пропустить». На настольном
  браузере вопрос появляется через несколько секунд по таймеру.
- У номера строка агрегата за 30 дней: **«за месяц: 12 звонков, 3 без ответа, цена не
  совпала у 2»**. Нет звонков — строки нет.

## Что хранится и почему это не персональные данные

Схема `crowd`, таблица `signal`: `entry_id`, `device_ref`, `day`, `outcome` (0 неизвестно /
1 дозвонился / 2 не ответили), `price_mismatch`, `updated_at`. Первичный ключ —
`(entry_id, device_ref, day)`.

- `device_ref` — HMAC от локального `install_id` с ключом приложения (`PAYLOAD_SECRET`);
  тот же `install_id`, что у записи поездок (`lib/install-id.ts`). Ни номера звонившего,
  ни адреса, ни аккаунта: сигнал анонимен по построению. Дамп базы не отвечает «какое
  устройство», обратный перебор без ключа невозможен.
- **Анти-накрутка = первичный ключ:** второй сигнал того же устройства по тому же номеру
  в тот же день перезаписывает свою строку. Сто нажатий за день весят одно.
- Сигнал принимается только по **опубликованной** записи (те же access-правила, что и у
  всего мира): по черновикам и чужим id — 404.
- Срок жизни строки — 90 суток, чистит регламент (`pruneCrowdSignals` в часовом тике
  планировщика). Агрегат считается за 30.

## Где в коде

`lib/crowd-ddl.ts` (DDL), миграция `20260903_120000_crowd_signals`, `lib/crowd-signals.ts`
(запись, агрегат, чистка, строка для карточки), `app/(app)/api/signal` (POST, без сессии),
`components/CallPhones.tsx` (телефоны + вопрос), `components/DirectoryList.tsx`
(агрегат под номером; страницы передают `stats`). Проверка — раздел `crowd` в
`scripts/check-track.mjs`.

## Что дальше (не в этом спринте)

Персоналу — сводка «номера без ответа за месяц» в админке, чтобы перепроверять карточки.
Порог «мёртвый номер» (например, ≥ 5 звонков и ≥ 80 % без ответа) — показывать
предупреждение у номера. Оба шага — после того, как накопится хоть месяц сигналов.

## Второе применение сигналов: порядок в «Быстром наборе» (2026-09-10)

Сигналы перестали быть только строкой под номером: по ним считается порядок блока
«Быстрый набор» на главной (`docs/HOT_NUMBERS.md`, `lib/hot-numbers.ts`).

Для витрины заведена отдельная функция `entryReach` — она считает **разные устройства**
(`count(DISTINCT device_ref)`), а не строки. Разница существенна: строка уникальна по
`(entry_id, device_ref, day)`, поэтому одно устройство, звонящее месяц подряд, даёт
тридцать строк и одно устройство. Для карточки верны строки («12 звонков за месяц»), для
витрины — устройства: это та величина, которую нельзя накрутить, не собрав тридцать разных
телефонов.

🔻 **И место в витрине решают только подтверждённые дозвоны** (`outcome = 1`), а не сам факт
нажатия. Иначе получался бы замкнутый круг: витрина показывает номер, тап по нему пишет
строку с `outcome = 0`, строка поднимает счётчик, счётчик держит номер в витрине. Такой
список самоподдерживается, и владельцу нечем ответить бизнесу, спросившему «почему не я».
`outcome = 1` ставит человек рукой, ответив «Да», — круг разрывается там, где нужен второй,
осознанный жест.
