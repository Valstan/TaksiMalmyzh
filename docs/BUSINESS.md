# Кабинет бизнеса и вызовы с адресом — спринт 8 (Фаза 2)

Построено 2026-09-03. Бизнес входит через ЕСА, подтверждает свой номер, правит карточку и
получает вызовы с адресом.

## Путь бизнеса

1. **Вход** — «Войти» в шапке → ЕСА (пароль или ВК). Аккаунт создаётся сам (посетитель).
2. **«Это мой бизнес»** на своей карточке в справочнике → заявка персоналу.
3. **Подтверждение звонком.** Персонал в `/kabinet` видит заявку с номером из справочника,
   звонит по нему и нажимает «Позвонил, подтверждаю». Тот, кто отвечает по номеру, и есть
   бизнес; самоподтверждения нет (SMS-шлюза нет, чужой «владелец» на карточке — вред).
4. **Кабинет** `/kabinet`: описание, часы работы, цены — правит сам. Название, телефоны и
   категорию меняет персонал (их проверяли звонком).
5. **Вызовы.** На карточке с владельцем у посетителя есть «Вызвать с адресом»: адрес из
   поиска спринта 1 (или руками), телефон для обратного звонка, примечание. Бизнес видит
   вызовы в кабинете, помечает «видел» / «выполнен». В шапке у владельца — «кабинет (3)»
   с числом непросмотренных: это и есть уведомление (в приложении, как §8.8; push/SMS —
   отдельное решение владельца).

## Что хранится

Схема `market`, DDL — `lib/market-ddl.ts`, миграция `20260903_160000_business`:

- `market.claim` — заявка (`entry_id`, `user_id`, `status` 0/1/2), одна на пару.
- `market.request` — вызов: `entry_id`, `customer_user_id` (если вошёл), `address`,
  `lat`/`lng`, `phone`, `note`, `seen_at`, `done_at`. **Телефон и адрес клиента —
  персональные данные**, которые клиент сам передаёт бизнесу; живут **30 суток**
  (`pruneRequests` в часовом тике), правовые тексты и согласия — спринт 7.
- `entries`: новые поля `description`, `hours`, `owner` (связь с `users`, только персонал в
  админке).

## Права (важно)

С появлением посетителей правило записей справочника «вошедший может править» стало
дырой: посетитель с сессией менял бы номера через REST. Закрыто в этом спринте:
`create/update/delete` — только `superadmin`; посетитель читает опубликованное и свои
карточки. Правка владельцем идёт через `/api/cabinet` → `updateOwnCard`, который сверяет
`owner_id` с сессией и меняет только описание, часы и цены.

## Не в этом спринте

- **Собственный домен бизнеса** (уровень `business` матрёшки): нужен слаг у записи и решение
  владельца, кто платит за домен. Кабинет теперь есть, так что домен перестал быть
  обещанием без исполнения — можно строить по запросу.
- **Push/SMS бизнесу** — отдельное решение (§8.8).
- **Телефония в приложении** — `tel:`, как и было.
