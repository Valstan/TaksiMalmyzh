# Быстрый набор — 3–5 номеров над плашками

Решение владельца 2026-09-10: «самые горячие телефоны высвечиваются в небольшом списке над
плашками (3–5 телефонов с названиями организаций), ну типа рекламного баннера».

**Выглядит как баннер, устроен наоборот: место здесь не покупается и не назначается
руками.** Порядок считает `lib/hot-numbers.ts`, и он детерминирован — при тех же данных и
той же дате результат один и тот же у всех, кто открыл сайт.

## Замкнутый круг, из-за которого блок чуть не сломался по построению

Витрина показывает номер → человек тапает → тап пишет строку в `crowd.signal` → строка
поднимает счётчик → счётчик держит номер в витрине. Список самоподдерживается: попавший в
него остаётся навсегда просто потому, что попал первым, а владельцу нечем ответить бизнесу,
спросившему «почему не я». Дневная ротация это **не лечит** — она перемешивает внутри
ступени и не умеет понижать.

Круг разорван выбором величины. Строка с `outcome = 0` создаётся **самим нажатием** на
`tel:`. Строку с `outcome = 1` ставит человек рукой, ответив «Да» на вопрос «дозвонились?».
Порядок считается по `answered`, то есть по второму, осознанному жесту, которого одним
показом в витрине не добиться.

## Правило отбора

**Сначала исключения** — витрина это рекомендация, и она обязана уметь молчать:

1. у записи нет ни одного телефона;
2. больше половины устройств не дозвонилось (`noAnswer >= 3` и `noAnswer * 2 > answered +
   noAnswer`);
3. карма организации явно отрицательная (`down - up >= 5`).

При нуле сигналов ни одно исключение не срабатывает — все счётчики нулевые, и первые дни
жизни сайта они не мешают.

**Затем ключи, лексикографически:**

| Ключ | Что это |
|---|---|
| ступень охвата ↓ | `answered >= 20` → 3, `>= 8` → 2, `>= 3` → 1, иначе 0 |
| качество ↓ | `(answered − 2·noAnswer) + (карма up − down)`, зажато в ±20 |
| дневная ротация ↑ | детерминированный хэш от «дата: id» |
| id ↑ | чтобы порядок был полным |

Ступени, а не сырое число: разница между 19 и 20 дозвонами не значит ничего, а между 2 и 20
значит всё. Ротация детерминированная, а не случайная: два человека, открывшие сайт в один
день, обязаны видеть одно и то же, иначе «почему у меня не так» становится вопросом без
ответа. Меняется раз в сутки — иначе первые попавшие прописались бы навсегда.

Какой из номеров карточки показать — с лучшей кармой (`up − down`), при равенстве первый.
Ключ номера берётся из `lib/phone-key.ts`, того же, что у кармы: своей нормализации здесь
нет и быть не должно, иначе карта промахивалась бы и «номер с лучшей кармой» молча
вырождался в «первый в массиве».

## Подпись обязательна

Под блоком стоит строка, объясняющая, откуда порядок. Без неё «типа рекламный баннер»
человек прочитает **как рекламу**, то есть как проданное место, и перестанет верить
остальному справочнику тоже.

Подписи две, а не одна на все случаи:

- есть подтверждённые дозвоны — «Чаще всего дозваниваются за последний месяц. Место здесь
  не покупается: порядок считает сайт по вашим же отметкам „дозвонились“»;
- их нет — «Пока просто из справочника — по мере ваших отметок „дозвонились“ список начнёт
  меняться. Место здесь не покупается».

Обещать «самые нужные», когда данных нет, было бы враньём.

## Границы

- Блока нет, если кандидатов меньше трёх: список из одного номера — не список.
- Кандидаты — только опубликованные записи домена, отобранные Payload с
  `overrideAccess: false`. Условия «опубликовано» в SQL агрегатов нет: это была бы вторая
  копия гейта публикации.
- Записи читаются одним запросом на всю страницу — тем же, из которого строится список на
  категорийном домене.
