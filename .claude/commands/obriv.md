Был **обрыв интернета/сессии**. Не паникуй и **не переделывай вслепую то, что уже сделано** — сначала восстанови картину из «земли» (git/файлы/PR), потом продолжи прерванную нить.

## 1. Реконструируй состояние из ground truth

```bash
git branch --show-current
git status --short
git log --oneline -6
git stash list
```
- Рабочее дерево чистое? Незакоммиченные правки — завершённые или оборванные на полпути?

## 2. Сверь с PR и фоновыми задачами

```bash
gh pr list --head "$(git branch --show-current)"
gh run list --limit 3   # CI/деплой мог идти в момент обрыва
```
- PR существует/открыт/смержён? Не задвоить создание.
- Dev-сервер, если запускался, — не плодить дубли (`netstat -ano | grep ':<порт>'`).

## 3. Проверь целостность недавно записанных файлов (грабля харнесса)

Обрыв может совпасть с **битой записью файла**: лишний `NUL`-байт (или UTF-16/BOM) → git показывает файл как **`Bin`** в `git diff --stat`.

```bash
git add -A && git diff --cached --stat   # любой исходник как "Bin" → подозрение
```
Если код-файл показан бинарным — вычистить NUL, пересохранить UTF-8:
```bash
node -e "const fs=require('fs');const f=process.argv[1];const b=fs.readFileSync(f);const n=[...b].filter(x=>x===0).length;console.log(f,'NUL',n);if(n)fs.writeFileSync(f,Buffer.from([...b].filter(x=>x!==0)))" '<путь>'
```

## 4. Реконсиляция последнего действия

Сопоставь последнее намерение (из контекста диалога) с фактическим состоянием файла. Не уверен — **перечитай** участок файла (Read), не доверяй памяти.

## 5. Если трогался код — перепроверь гейты проекта

Для сайтов на Payload/Next: `corepack pnpm lint && corepack pnpm typecheck && corepack pnpm build` (⚠️ `build` требует локальный Postgres — Payload читает БД на пререндере, образец `.env.example`). Для проектов без сборки (репо-скелет / статика) — пропусти.

## 6. Доложи и продолжи

`После обрыва: ветка <X>, последний коммит <Y>, дерево <чисто/N правок>, PR #<N> <состояние>. Потеряно: <ничего/…>. Продолжаю: <следующий шаг>.` — и продолжай прерванную работу.
