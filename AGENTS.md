## Начало и завершение работы

В начале работы:

1. Синхронизируй **только этот** репозиторий (`git fetch`, затем безопасный fast-forward).
2. Соседние репозитории, включая `../brain_matrica`, никогда не синхронизируй: ни `fetch`,
   ни `pull`, ни `checkout`, ни иные синхронизирующие/изменяющие команды — только чтение
   (мандат владельца 2026-08-04: проект или Мозг могут одновременно работать в своей
   локальной копии, в том числе держать ещё не запушенную почту).
3. Входящие письма читай в **два канала**: локальная копия
   `../brain_matrica/mailboxes/TaksiMalmyzh/from-brain/*.md` **плюс** тот же путь на
   GitHub `main` репозитория `brain_matrica` через API/веб, без clone/fetch/pull.
   Набор писем = объединение каналов. Одноимённое письмо с разным содержимым: свежесть
   определяется историей именно этого пути — незакоммиченная локальная версия свежее;
   иначе сравнивается последний локальный коммит файла с последним коммитом пути на
   GitHub; если порядок не определяется — прочитай обе версии, явно отметь конфликт и
   ничего не перезаписывай. Свежесть одного репозитория или письма не переносится на
   другие проекты и письма.
4. Прочитай `docs/SESSION_HANDOFF.md` и проверь `git status`/последние коммиты.

В конце значимой работы обнови `docs/SESSION_HANDOFF.md`, сохрани изменения через PR и
оставь свой репозиторий запушенным и чистым; `../brain_matrica` не трогай — только
чтение. Подробные исполняемые памятки пока
лежат в `.claude/commands/start.md`, `close_session.md` и `obriv.md`; несмотря на имя
каталога, их workflow применим к любому агенту.

## Git и совместная работа нескольких агентов

- `main` защищён логически: ветка → коммит → push → PR → squash merge. Прямой push в
  `main`, force-push и `reset --hard` запрещены.
- Один агент — одна задача, отдельная ветка и, при одновременной работе, отдельный
  `git worktree`. Не запускай двух пишущих агентов в одном рабочем дереве.
- Перед правкой проверяй `git status`. Незнакомые изменения считай чужими: не удаляй,
  не форматируй попутно, не включай в свой коммит и не прячь в stash.
- Не переключай ветку в рабочем дереве, которое может использовать другой агент.
- Объявляй границы файлов/задачи в описании PR. Если границы пересекаются, второй агент
  ждёт merge первого и ребейзит/обновляет свою ветку до начала правок.
- Один PR должен решать одну задачу. Коммиты — Conventional Commits.
- После обрыва сначала восстанавливай фактическое состояние из Git/PR, не повторяй
  действия по памяти.

Git — механизм координации между моделями; чат одной модели не является источником
истины для другой. Долговечные решения живут в документации/ADR, состояние незавершённой
работы — в `SESSION_HANDOFF`, история — в коммитах и PR.

## Какие AI-файлы хранить в Git

Коммитить:

- `AGENTS.md` — общие правила и источник истины;
- `CLAUDE.md`, `GEMINI.md` — короткие адаптеры к `AGENTS.md`;
- `.claude/commands/` и `.claude/settings.json` — общие безопасные команды/ограничения;
- `docs/SESSION_HANDOFF.md`, проектную документацию и `mailbox/`.

Не коммитить:

- локальные разрешения и персональные настройки (`.claude/settings.local.json`);
- кэши/сессии `.codex/`, `.gemini/` и временные планы вне проектной документации;
- `.env*`, ключи, токены, логи и временные файлы.

Секреты не должны жить в репозитории даже под защитой `.gitignore`.

## Публичный репозиторий — recon-поверхность

Репозиторий публичен (с 2026-08-17). Ограничение сформулировано через **свойство
информации, а не через канал публикации** (#189, D-038): хостнеймы и IP, имена/алиасы
боксов и SSH, порты, пути на сервере, состав жильцов серверов и имя хостера **не
кладём в отслеживаемые файлы вообще** — ни в документацию, ни в код, ни в комментарии,
ни в письма `to-brain`. Место таких деталей — карточка проекта на brain-стороне
(приватна) или env/секреты вне репозитория. Публичный прод-домен продукта
(`такси.вмалмыже.рф`) секретом не является. Если инфра-деталь всё же попала в историю —
историю не переписываем (это ничего не отзывает, #060): чистим отслеживаемые файлы,
а реальное лечение — смена/ротация на стороне инфраструктуры, если владелец решит.

Публичные домены продукта — все домены матрёшки (`такси.`, `позвони.`, `услуги.`,
`магазины.` и далее) — секретом не являются и живут в отслеживаемом реестре `lib/sites.ts`.
Секретна не строка домена, а связь домена с боксом: адрес, порт, путь, имя службы.

## Продуктовые ограничения до начала постройки

M0 выполняется до scaffold и схемы БД:

1. Письменно спроектировать приватность геоданных: частоту/прореживание, точный срок
   хранения, доступ доверенного контакта и извлечение трассы при потере телефона.
2. Живым probe проверить Яндекс Карты/2ГИС: лимиты, бесплатный уровень, доступность и
   цену роста.
3. Получить отдельный go владельца на активную разработку Фазы 1.

Фаза 1 должна учитывать: псевдонимность пассажира, server-side authz, серверную копию
точек с идемпотентными пачками и досылкой, Screen Wake Lock, явное состояние записи,
штатные разрывы трассы, 152-ФЗ и ограниченную ёмкость хранилища. SSO предназначен
только для таксопарков Фазы 2.
